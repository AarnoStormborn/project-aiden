# v0.3 — Eval runner, with tasks mined from this repo

**Status: complete and verified live.** 609 tests, all gates green. Mining yielded 6 validated tasks
from this repo; a live run against `htmltext--title_of` resolved in 12 turns for $0.0071; and the gate
was exercised against identical, regressed, and expensive candidates.

**Goal:** a way to tell whether a change to Aiden helps or hurts. Everything remaining depends on it:
Tier-2 self-update is gated by an eval (`architecture` §4.5), continual learning is meaningless
without a score, and the write path is currently only unit-tested.

Today the only evaluation is `scripts/acceptance_v01.py`, which asserts correctness on a single
sample and says so in its own output.

---

## 1. The three things that shape the design (`research/05`, `architecture` §12)

| Principle | What it means here |
|---|---|
| **Inference and grading are separate halves** | The agent produces a patch; an oracle decides. The seam is what lets harness configurations be compared without touching the answer key |
| **Private repo-derived tasks are the real eval** | FeatureBench collapsed 74.4% → 11.0% going from issue-level to feature-level tasks. A hand-written smoke test measures nothing |
| **`< 3 pp` is noise** | Infrastructure alone moved Terminal-Bench 2.0 by 6 pp. So: paired runs, ≥3 seeds, and `resolved @ cost` rather than a single number |

## 2. Mining: blank a function, keep its tests

This repo has ~10 commits, so mining merged PRs yields nothing. The mechanical alternative works on
any Python repo:

```
1. parse a module with ast; find functions that a test file references by name
2. replace the body with `raise NotImplementedError(...)`, keeping signature and docstring
3. VALIDATE the task:
     blanked  -> the referenced test must FAIL   (F2P)
     restored -> the same test must PASS         (P2P)
     neither file may be the test itself
4. the oracle is that test's node id, run by pytest
```

**Step 3 is the whole design.** A task whose test passes with the body blanked is not a task, and
without that check the suite would silently fill with unanswerable or already-passing items. A mined
task is only adopted when it can be shown to discriminate.

## 3. Isolation

One `git worktree` per task, detached at the base commit, with the blanked module written in. Reasons:

- The agent's writes cannot reach the real working tree, and each task starts from byte-identical
  inputs.
- `git diff` in the worktree *is* the patch, which is what the oracle is graded against and what a
  report can show.
- Disposable: removed after grading, so the disk cost is per-task temporary.

The agent runs with `cwd=<worktree>`, and the existing path policy already confines writes there.

## 4. What is measured

Per task, per seed:

```
resolved        the F2P test passes after the run
cost_usd        real spend, from the session log
turns           agent turns used
tool_calls      including failed and declined
patch_lines     size of the produced diff
infra_failure   the run could not even be attempted (setup, timeout, provider)
```

Aggregated: `resolved @ cost` — the pair, never the rate alone, because a harness that resolves more
by spending 10x has not improved.

**Behavioural metrics alongside pass/fail.** `research/09` records a nanoGPT case where a harness
effect was real and pass/fail missed it entirely. So the report also carries *how* the run went:
first-edit turn, run-after-edit, and whether the agent checked its work before claiming done.

## 5. The gate

`aiden eval gate --baseline run.json --candidate run.json` exits 0 only when:

- `resolved_delta >= 0`, and
- `cost_delta <= +15%`, and
- no new infrastructure failures, and
- the delta clears the noise floor: `> 3 pp`, or a paired comparison over ≥3 seeds.

This is the function Tier-2 self-update will call. It is built and tested now so that the rule exists
before anything can propose changing Aiden's own source.

## 6. Build order

| Step | Deliverable | Test |
|---|---|---|
| 1 | `eval/task.py`: task model, JSON round-trip | |
| 2 | `eval/mine.py`: find candidates, blank bodies, validate F2P/P2P | mining this repo yields ≥1 valid task; an already-passing case is rejected |
| 3 | `eval/sandbox.py`: worktree per task, patch extraction, cleanup | two sandboxes are independent; cleanup leaves no worktrees |
| 4 | `eval/oracle.py`: run the F2P node ids, parse the result | passes/fails correctly; parses pytest's failure list |
| 5 | `eval/runner.py`: run the agent against a task, capture patch/cost/turns | fake agent that restores the function grades resolved; a no-op grades unresolved |
| 6 | `eval/report.py`: aggregate, seeds, `resolved @ cost`, gate logic | gate rejects a +2 pp win as noise; rejects a cost blow-up |
| 7 | `aiden eval mine\|run\|report\|gate` | CLI smoke |

## 7. Acceptance

1. `aiden eval mine` derives valid tasks from this repo and **rejects** candidates that do not
   discriminate.
2. A full run against a fake agent that restores the blanked function grades `resolved`, and a fake
   agent that does nothing grades unresolved — with no network.
3. The gate refuses a within-noise improvement and a cost regression, and accepts a real
   improvement.
4. One live run against a real mined task, with the real agent, produces a patch and a verdict.
5. Existing suites stay green: 573 tests, frame budget, provider smoke.

## 8. The real yield, and what it says

```
accepted 6 task(s)
  checkpoint--begin      aiden/checkpoint.py (begin)          15 test(s)
  config--project_slug   aiden/config.py (project_slug)        3 test(s)
  diffutil--unified      aiden/diffutil.py (unified)          10 test(s)
  htmltext--title_of     aiden/htmltext.py (title_of)          3 test(s)
  auth--env_var_names    aiden/providers/auth.py               9 test(s)
  catalog--provider      aiden/providers/catalog.py            7 test(s)

rejected 40 candidate(s)
```

Forty rejections against six accepts is the validation working, not the miner failing. The dominant
reason is `blanking the body broke no test` — the tests that reference a symbol often assert on
something else, or the function's contract is already covered elsewhere. A miner without the
validation step would have produced forty-six tasks, forty of them unanswerable or free.

Two small tasks turned out to be too *cheap* to be interesting (`title_of` is three lines), which is
the opposite failure and worth naming: validation proves a task discriminates, not that it is hard.

One rejection is a performance signal: `mine--candidate_functions` timed out after 120 s because
`tests/test_eval.py` takes ~110 s, and validation runs the referencing test *file*. Mining cost scales
with the slowest file a candidate appears in. Recorded rather than hidden — it is the reason mining
this repo takes minutes.

## 9. The bug this milestone found in itself

Mining took **39 minutes and created 3,523 git worktrees** on one call. The cause was a loop the
design invited: validation runs the test *file* that references a symbol, and when that file is the
eval suite, it calls `mine()`, which validates by running the eval suite again. Each level created
more worktrees, and because `git` gets slower as worktrees accumulate, the cost was quadratic on top
of the recursion. The full test suite reported **8.5 hours**.

Fixed in two places, because one guard would have left the other hole open:

1. **A sandbox refuses to nest.** `Sandbox.create()` raises when `AIDEN_EVAL_ACTIVE` is set, and
   `Sandbox.run()` sets it for every child process — so the marker reaches the tests being graded.
   `allow_nested=True` exists for a test that deliberately grades a sandbox-creating test.
2. **The eval suite is never an oracle.** A candidate referenced only by `test_eval.py` is rejected
   with that reason, because grading an eval with an eval is self-referential whatever the guard does.

After the fix: mining is **16 seconds** and leaves **zero** worktrees, and the suite runs in 2.8
minutes. Two regression tests exist that would have caught it — one counting worktrees across a
`mine()` call, and one asserting a sandbox leaves nothing registered. The second matters because
nothing in the original tests checked cleanup at all, which is why thousands of worktrees could
accumulate unnoticed.

## 10. Honest limitations

- **The set is small.** A single repo yields a handful of valid tasks, so intervals will be wide and
  a 1-task difference means nothing. The report must state the count next to the rate rather than
  implying a trend.
- **Blanked-function tasks are narrower than real bugs.** They test "can it restore behaviour from
  tests", not "can it diagnose an unfamiliar failure". Recorded as such, not dressed up.
- **Non-determinism is the model's, not the harness's.** Seeds vary the agent, so a paired
  comparison needs the same tasks and the same seeds to say anything about the harness.
