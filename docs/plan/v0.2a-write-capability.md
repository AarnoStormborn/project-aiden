# v0.2a — Write capability with guards, checkpoints, and approval

**Status: complete and verified live.** 442 tests, ruff/mypy/pytest green, v0.1 acceptance still
5/5, provider smoke still 5/5. `bash` deliberately still absent.

v0.1 could only read, which capped the project: an eval oracle is derived from *patches*
(`research/05`), self-update requires editing its own source, and continual learning needs a change
and its outcome. This closes the `3 of 7` tools gap for the two that carry the most value, and
deliberately leaves `bash` out until the guard model has proven itself.

**Decisions taken:** approval on **every** write; a checkpoint before each turn's first write.

---

## 1. What ships

| Piece | Why |
|---|---|
| `edit(path, old_string, new_string, replace_all?)` | exact-string replace as primary. Generated unified diffs applied on only **48.7%** of attempts before repair ([r02] §4) |
| `write(path, content)` | whole-file path for new/small files; `gemini-exp-1206` scored 80.5% on `whole` vs 69.2% on `diff` — format fit is model-specific |
| Read-before-edit, enforced | `ReadState` already records SHA hashes and nothing checks them ([r02] §6). Hashing beats mtime |
| Unique-match requirement | An ambiguous replace is a silent wrong edit; refuse and report the candidate lines |
| Post-edit validation gate | Parse/compile the result and return errors to the model. SWE-agent's lint gate alone was worth **+3.0 pp** ([r02] §2) |
| `aiden/tools/policy.py` | declarative path classes, so the Tier-2 self-update rules can be layered later without touching the tools |
| `aiden/checkpoint.py` | pre-image snapshots per turn under `~/.aiden/`, so `/undo` is a lookup, not a rescue ([arch] §7) |
| Approval on every write | inline diff + y/n, recorded in the session log |
| `Approval` cell + diff rendering | the spec's cell type; `diff_added`/`diff_removed` tokens already exist and are unused |

**Not in this milestone:** `bash`, the full alt-screen review overlay, hunk-level accept/reject,
auto-commit of accepted edits, and the Tier-2 self-update policy.

## 2. The gate chain, in order

`research/01` §permissions: each class of failure returns an **error tool result**, never raises, so
the model can see and correct it. Deny beats allow; a hook cannot upgrade permissions.

```
1 schema      arguments parse, required fields present
2 semantics   path inside cwd? inside .git? binary? exists (for edit)?
3 read-state  file read this session, and hash unchanged since
4 match       old_string found exactly once (or replace_all)
5 policy      Block | Allow, with a reason the model can read
6 approval    the user sees the diff and decides
7 exec        apply; checkpoint the pre-image first
8 validate    parse/compile the result; failure -> error result, edit kept but reported
```

Step 8 is the one that earns its keep: a syntactically broken edit that the model *sees* is a
correction; one it does not see becomes a debugging session.

## 3. Checkpoints

Pre-image snapshots, not git commits. Reasons:

- Precise: only files the turn actually modified.
- Works with untracked files, which `git stash` does not capture by default.
- Does not touch the user's branch or index — auto-committing to someone's working tree is
  intrusive, and that is a Tier-2 concern, not this one.

Layout: `~/.aiden/checkpoints/<session_id>/turn-<n>/` with a `manifest.json` mapping each path to
its backup file and pre-image hash. Restoring writes the originals back and reports what changed.

Git stays the *durable* second store ([arch] §7); the snapshot is the fast, precise one.

---

## 4. Approval

- **Interactive:** an inline `Approval` cell renders the diff, then blocks on y/n at the prompt.
  Anything other than an explicit yes is a no.
- **Non-interactive (`aiden ask`, pipes):** the default is **deny**, and the model is told so with a
  reason. `--allow-writes` opts in with a warning. A non-interactive run must never silently write.
- **Every decision is logged** (approved/rejected, by whom), because the transcript is the audit
  trail — `architecture` §4.5's "the Refiner cannot write code" is enforced by the tool layer, not
  by asking the prompt nicely.
- Rejection returns an error result carrying the user's reason, so the model can adapt rather than
  retry blindly.

## 5. Build order

| Step | Deliverable | Test |
|---|---|---|
| 1 | `policy.py`: path classes + decisions | `.git` denied, cwd escape denied, normal edit allowed |
| 2 | `edit` + `write` tools | unique-match, zero-match, multi-match, whitespace-tolerant fallback, new file |
| 3 | read-before-edit + hash staleness | edit without reading is refused; edit after external change is refused |
| 4 | post-edit validation gate | a broken edit returns the syntax error to the model |
| 5 | `checkpoint.py` + loop wiring | checkpoint taken once per turn, before the first write |
| 6 | approval events + loop wiring | deny path, approve path, logged decisions |
| 7 | TUI `Approval` cell + diff render | golden frame; prompt accepts/rejects |
| 8 | CLI flags + docs | non-interactive default denies |

## 6. Acceptance

1. `aiden tui` can be asked to add a function to a file; the diff appears, `y` applies it, the file
   is correct, and `/undo` restores it.
2. Every refused case returns a readable error result and the run continues: unread file, stale
   hash, ambiguous match, missing match, denied path, rejected approval, broken syntax.
3. A non-interactive run with writes attempted **cannot** modify anything without `--allow-writes`.
4. The session log records every write attempt, its decision, and its outcome.
5. Existing suites stay green: 355 tests, provider smoke, acceptance 5/5, TUI perf budget.

## 7. What building and testing it found

**The gate chain earned its keep immediately.** Each of these was caught by a test rather than by a
user:

1. **`/undo` shipped as unreachable dead code.** The handler was wired into the dispatch chain but the
   command was never *registered*, so `Command.known` was false, the handler could not run, and
   `/undo` silently printed help. Found by typing it at a live session. Fixed by deriving the help
   text and the known-command set from one table, plus a test that pins the handler keys to it — the
   class of bug, not just the instance.
2. **Checkpoints were captured before approval**, so every declined proposal left an empty checkpoint
   for `/undo` to walk through. The capture now happens after the decision and before the change.
3. **`/undo` left an empty directory behind.** Restoring the file state is not the same as restoring
   the visible state, so emptied directories are now pruned up to (but never including) the project
   root.
4. **The approver had to become async.** Reading the terminal in prompt_toolkit can only happen inside
   a running event loop, which this project already learned when the TUI's first launch crashed on
   `asyncio.run` nesting.
5. **`preview` is not a Protocol member.** Making it one forced read-only tools to declare a no-op. It
   is discovered through `preview_of()`, which returns `None` when there is nothing to show.

Two design points that survived contact:

- **A no-op preview means no approval prompt.** If the tool is about to refuse anyway (bad path, no
  match, stale read, denied path), there is nothing for a human to decide, and the tool's own error
  result is the better answer.
- **A broken edit is kept and reported**, not silently reverted. The syntax error is the information
  the model needs to fix it, and reverting would hide what it actually produced.

## 8. Open questions

- **Should an applied-but-broken edit be auto-reverted?** Keeping it means the model can fix it in
  place (and sees the error); reverting means the tree is never broken. Current plan: keep it and
  report, because the error is the information the model needs.
- **`replace_all` is a foot-gun.** It is included for repeated identical lines (imports, boilerplate)
  but it should probably require an explicit count so the model states what it expects to change.
- **What does `/undo` undo?** Nearest plan: the most recent checkpoint, with a count, so
  `/undo 3` walks back. Forking the session tree is the M4 answer and is not here yet.
